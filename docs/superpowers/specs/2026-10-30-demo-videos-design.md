# MAPP Demo Videos — Design

Date: 2026-10-30

## Intent

The faculty coordinator (ma'am) needs demo videos to present MAPP to the HOD. They must show how the portal works end to end, from first login through every main feature, as a polished walkthrough a non-technical audience can follow without a live presenter.

Two videos:

1. **Student demo**: what a student sees and does.
2. **Faculty demo**: what a faculty member sees and does, recorded with a **Faculty Advisor** account so one video covers both the guide features and the advisor features (this avoids a third video).

The admin portal is out of scope.

## Goals

- Real app, real flows: record the actual MAPP UI driving the real Supabase backend. No mockups, no faked screens.
- Each video stands alone: AI voiceover narration plus on-screen captions, so it plays without anyone explaining it.
- Paced for an HOD demo: unhurried, every screen explained once, no dead time. Target ~5–7 min for the student video and ~4–6 min for the faculty video. Pacing comes from the narration length, not a fixed duration.
- Repeatable: a script can reseed the demo data and re-record if ma'am asks for changes.

## Non-goals

- The admin portal.
- Editing in a video editor by hand. Everything is generated by script.
- Showing faculty screens inside the student video.

## Anti-goals (failure even if it "works")

- Visible errors, toasts saying "failed", spinners stuck on screen, or empty tables where data should be.
- Touching or altering existing (non-demo) accounts or global settings (freeze / open windows) in the database.
- Leaking secrets on screen (service key, `.env`, DevTools).
- Robotic pacing where the narration talks over a screen that already changed, or the screen sits idle while nothing is said.

## Decisions made by the user

- **Backend:** the existing Supabase project in `.env` (`kyblefpovheanqyssqje`). It is live, but all data in it is dummy data, so adding demo accounts is acceptable. Mock auth mode no longer exists (removed in `9fb1223`).
- **Narration:** AI voiceover **plus** captions. Voice: edge-tts `en-IN-PrabhatNeural` (Indian English, male).
- **Student video covers two students:**
  - **Part 1, Student A (MOOC):** first login with the default password → forced password change → portal tour → MOOC request (CGPA ≥ 9) → status "Awaiting Faculty Advisor approval" → **advisor approves off-camera** (caption/voice says so; no faculty screen) → student sees "Your MOOC request is approved", with Minor and Application now locked.
  - **Part 2, Student B (Minor):** login → Minor page → approach a guide → guide accepts and forms the batch **off-camera** → Application Form unlocks → fill in the form → submit → download the Guide Acceptance PDF.
- **First login:** show the forced password change (at least for Student A).
- **Faculty video:** a Faculty Advisor account showing **guide + advisor** features: login (first-login password change) → Students Approached (accept/decline requests) → Batch Grouping (form a batch) → Faculty Advisor page (MOOC reviews: approve a request; class overview).
- **Names:** realistic dummy names (e.g. student "Arjun Kumar", faculty "Dr. Priya Raman"), not "Demo …".
- **Output:** 1080p MP4, two files.

## How it gets made (builder's calls, stated as defaults)

### Tooling
- **Playwright (Chromium)** drives a 1920×1080 browser and records video. Lives in its own folder (`tools/demo-video/`) with its own `package.json`, so the app's dependencies stay untouched.
- **edge-tts** (Python, `pip install edge-tts`) produces one narration clip per step.
- **ffmpeg** (already installed) handles assembly: video + timed narration clips + captions + intro/outro title cards → final MP4 (H.264, AAC).
- The app runs locally (`next build && next start`) against the Supabase project from `.env`, so nothing depends on the Vercel deployment.

### Demo data (seed script)
A seed script uses the service-role key and the existing importers (`src/lib/server/importers.ts`: `upsertStudent`, `upsertFaculty`, `upsertAdvisor`) so the accounts look exactly like real imported ones (password = reg no / emp ID, `must_change_password = true`). It creates:
- a **dedicated demo section** that no existing Faculty Advisor is mapped to (format must pass the validators). As of 2026-10-30, A1, A2, B1 and B2 are taken, so e.g. `C1`. The portal is currently not frozen,
- **Dr. Priya Raman**: faculty and Faculty Advisor of the demo section (the faculty video account),
- a **second guide** (e.g. "Dr. Karthik S") whom Student B approaches, so the faculty video's lists stay clean,
- **Student A** (MOOC) and **Student B** (Minor) plus B's batch partner, all in the demo section,
- **extra students** in the demo section who, before the faculty recording, send Minor requests to Dr. Priya (so Students Approached has pending requests to accept and Batch Grouping has students to group) and one who sends a MOOC request (so MOOC reviews has something to approve). Enough data that the class overview doesn't look empty.

Pre-recording actions (requests sent by extra students) are done by signing in as those students in the script and calling the same RPCs the UI uses, never by writing tables directly. That keeps the data consistent with what the app enforces.

Accounts not shown logging in for the first time (Student B, partner, extras) get their password changed by the script beforehand, so they skip the forced-change screen.

### Off-camera steps
Between recorded segments, the script signs in as the relevant faculty and calls the real RPCs (`respond_mooc_request`, accept request, form batch). On screen, a short caption card plus narration covers the gap (e.g. "The Faculty Advisor reviews and approves the request…"), then the student view refreshes and shows the new state.

### Recording and sync
- Steps are defined as data: `{ narration, caption, actions }`.
- TTS clips are generated first, and their durations are measured.
- During the Playwright run, each step logs its start timestamp, performs its actions with human-like pacing (typing delay, short pauses), and holds until its narration clip has finished.
- Playwright's video has no mouse cursor, so an injected overlay draws a visible cursor and a click ripple.
- Captions are generated as an SRT from the step timestamps and burned in. Narration clips are placed at those timestamps.
- An intro card (MAPP title, "Student Portal Demo" / "Faculty Portal Demo") and an outro card.

### Safety checks
- Before recording, the script checks that the portal is open (not frozen) for students and faculty. **If it is frozen, it stops and reports. It never changes global settings itself.**
- Only accounts the seed script created are touched.
- A separate **cleanup script** deletes the demo accounts and their rows. It is not run automatically. The user decides when.

### Output
- `demo-output/MAPP-Student-Demo.mp4` and `demo-output/MAPP-Faculty-Demo.mp4` (gitignored), plus the SRT files.

## Left to the builder
- Exact names, reg numbers, emp IDs, section code and passwords for the demo accounts (realistic, within the validators).
- Exact narration wording: clear, formal, and short per screen, aimed at an HOD audience.
- Whether to show a still of the downloaded Application PDF (e.g. rendered to an image) at the end of Part 2.
- Dark or light theme: default to light.
- Fine pacing and pauses.
